# Corrections Log

Copy this file to the path named in `config.md`. It starts empty and fills itself as you use the
system.

---

## What this is for

When you change a line during review, that correction used to die in the chat. The next week the same
mistake got made again.

**The gap between what you were shown and what you approved is the highest-signal training data in
the system.** Nothing else captures it. Analytics measure what published. This measures what you
rejected, which is a much sharper signal about your taste.

Three rules keep it useful:

1. **Clean approvals log nothing.** Only edits are data.
2. **The rule gets written for the next post, not this one.** "Cut the second example" is a note.
   "One post, one idea: a second example is a second idea, not a free addition" is a rule.
3. **At three strikes, a rule graduates** out of this log into the file that owns it. The log stays
   short on purpose. A log nobody reads is worse than no log.

---

## Promotion routing

When a rule hits three strikes, move it here:

| Where it goes | When |
|---|---|
| `voice-lint.md` | Binary and checkable, applies to everything you write or send |
| `calibration/voice.md` | About register and how you sound, needs judgment to apply |
| `calibration/terms.md` | About a specific word, term, or named concept |
| `calibration/patterns.md` | About rhythm, length, or structure, and you can point at evidence |
| `reference/writing-mechanics.md` | Genuinely universal, would apply to anyone writing anything |
| Claude's memory | A preference about how the assistant should work, not about the content |

Once promoted, delete it from the standing table below and add a row to Promoted.
